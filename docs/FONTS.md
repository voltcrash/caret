# Adding fonts

Follow [basic contributions](CONTRIBUTING_BASIC.md) to fork and open a pull request.

1. Add the WOFF2 file to `frontend/static/webfonts/`. Filenames must not contain
   spaces or start with a number.
2. Add the font name to `KnownFontNameSchema` in `packages/schemas/src/fonts.ts`.
   Replace spaces with underscores; do not start the name with a number.
3. Add a matching entry to `Fonts` in `frontend/src/ts/constants/fonts.ts` with
   `fileName` set to the exact WOFF2 filename. Set `weight` when the font differs
   from the default weight of 400.

System fonts use `systemFont: true` instead of `fileName` and need no bundled file.
Font CSS and production previews are generated by the Vite font plugins.

## Manual optimization

Fonts are processed **manually**, never by install, dev, build or CI hooks.
Original inputs are immutable git blobs at `7699fef52`, verified against
SHA-256 values in `docs/font-evidence/baseline-inventory.json`. Fetch that
revision in shallow clones. Never feed generated files back into the tool.

```sh
vp exec python3 -m venv /tmp/caret-font-tools
vp exec /tmp/caret-font-tools/bin/pip install -r scripts/fonts/requirements.txt
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/generate.py
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/generate.py --check
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/validate.py
vp run --filter @caret/frontend check-assets fonts
```

Commit WOFF2 files, `scripts/fonts/output.json` and
`docs/font-evidence/after-inventory.json` together. Generation removes only
unrequested discretionary `ss*`, `cv*`, `salt`, `dlig`, `hlig`, `swsh`, `ornm`
features (except CommitMono, whose trim changed pixels) and glyphs unreachable from retained mappings/default shaping.
No caller enables these discretionary features. Default shaping, composition,
contextual alternates, kerning (including legacy `kern`), marks, glyph
instructions, global hint programs, bounding boxes and variable axes remain.
If the generated full face is no smaller, keep the exact original bytes.

All original cmap mappings remain, including supported Latin-1/Extended-A and
non-Latin scripts. System fonts and uploaded `LOCALCUSTOM` files are never
processed. CJK keeps system fallback. Gallaudet stays byte-identical: no
modification grant found. Font Awesome stays complete and unmodified. Primary
internal names avoid Reserved Font Names; Ubuntu uses its required `derivative`
naming. Public CSS/settings names stay stable. Full licenses, original copyright
notices and source checksums ship in `frontend/static/webfont-licenses`.

### Strict splitting remains blocked

The requested exact-cmap core/extended split was implemented and tested against
the original production build. It changes combining-mark placement and missing
glyph fallback; it is **not shipped**. Reproduce with:

```sh
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/generate.py --split --out /tmp/caret-font-split
```

See [evidence and merge gate](font-evidence/REPORT.md). The candidate retains
full faces, original CSS descriptors, preloads, fallbacks, loading gates and
service-worker behavior. No runtime integration change is needed. No new idle
precache or CSS embedding. The strict split/core-preload acceptance contract
is unresolved; do not treat this candidate as completing it.

## Visual/network proof

The manual Playwright suite uses the **built production Start Worker** and
existing PostgreSQL/auth fixture. Actual routes and all text-font specimens use
built CSS and real downloads. Fixed seeds include the crypto RNG; relevant
clocks, locale, theme, viewport, DPR and installed fallback fonts match. It waits
for requested fonts and records CDP rendered faces. No masks or pixel tolerance.

```sh
vp exec node frontend/scripts/ci-build.ts
# From frontend, before editing fonts; preserve this original build:
vp exec env FONT_PROOF=before vp exec playwright test font-proof.spec.ts --config=playwright.start.config.ts --project=start
vp exec env FONT_PROOF=repeat vp exec playwright test font-proof.spec.ts --config=playwright.start.config.ts --project=start
# Rebuild with candidate fonts before the after phase:
vp exec env FONT_PROOF=after vp exec playwright test font-proof.spec.ts --config=playwright.start.config.ts --project=start
# From root:
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/compare.py before repeat
vp exec /tmp/caret-font-tools/bin/python scripts/fonts/compare.py before after
```

Keep the same fallback fonts in every phase. The recorded Linux fixture adds a
checksummed, **unshipped** Noto Sans CJK SC font via
`FONTCONFIG_FILE=/tmp/caret-font-system/fonts.conf`; run `vp exec python3 scripts/fonts/system-fixture.py` to prepare it. Never reconstruct before images from optimized files. Use a clean
baseline checkout or preserve its built fixture before editing. Experimental
`FONT_PROOF_ASSETS` changes isolated specimens only, never actual route proof.

Rerun generation, repeatability, validation and visual/network proof after
changes to source fonts, tool/dependency versions, axes/features, font settings,
CSS descriptors, Unicode partition or fallbacks. New text/Unicode may change
actual downloads: audit routes and repeat network/visual proof. Browser/OS or
system-font changes require a fresh before/after pair. Inventory every new font,
read its actual license, update original-source provenance/checksums, then
regenerate from that original. Update the pinned baseline only for new original
sources; never point it to a commit containing optimized derivatives.

Follow [font guidelines](CONTRIBUTING.md#font-guidelines). For local validation,
follow [development setup](CONTRIBUTING_ADVANCED.md), then run from the repository root:

```sh
vp run --filter @caret/frontend check-assets fonts
```
